# ai-advent-agent — День 6. Первый агент

Учебное задание: CLI-агент на Java, который принимает запросы пользователя
из консоли, отправляет их в LLM через OpenAI-совместимый HTTP API
и выводит ответы в консоль. Агент поддерживает **многошаговый диалог**:
в пределах одного запуска учитываются предыдущие сообщения пользователя
и собственные ответы агента. Это по-прежнему **не** автономный агент:
без инструментов, планирования и хранения переписки на диске.

## Стек

- Java 21, Maven
- Jackson (JSON), `java.net.http.HttpClient` (HTTP) — без Spring и других фреймворков

## Структура классов

| Класс | Назначение |
|---|---|
| `com.example.Main` | Координация: параметры запуска (`--help`, `--plain`), цикл чата и диспетчер команд. Ни JSON, ни HTTP здесь нет. |
| `com.example.LlmAgent` | Отдельный агент: история беседы, формирование JSON-запроса с контекстом, HTTP-отправка, обработка ошибок, разбор ответа. Не зависит от терминала. |
| `com.example.ChatMessage` | Одно сообщение диалога: `record ChatMessage(String role, String content)`. |
| `com.example.TerminalUi` | Интерфейс терминального UI: приветствие, ввод, ответы, статусы, ошибки, справка. |
| `com.example.InteractiveTerminalUi` | Интерактивная реализация на JLine: редактирование строки, история ввода в памяти, Tab-автодополнение, спиннер ожидания, цвета. |
| `com.example.PlainTerminalUi` | Упрощённая реализация без цветов и анимации (`--plain`, `TERM=dumb`, перенаправленный ввод/вывод). |
| `com.example.AnsiSanitizer` | Обезвреживание управляющих последовательностей в отображаемом тексте. |
| `com.example.Config` | Чтение и валидация переменных окружения `LLM_API_KEY`, `LLM_API_URL`, `LLM_MODEL`. |
| `com.example.AgentException` | Понятная ошибка конфигурации или запроса (без секретов в тексте). |
| `com.example.SelfTest` (test) | Локальная проверка без платных запросов на встроенном JDK HTTPS-сервере. |

## Почему LlmAgent — отдельная сущность

Вся логика общения с LLM инкапсулирована в `LlmAgent`:

- публичный интерфейс — один метод `String ask(String userMessage)`;
- агент **владеет историей беседы**: завершённые пары user/assistant хранятся
  в его внутреннем списке (только в памяти, без сохранения на диск);
- `HttpClient` и `ObjectMapper` создаются один раз в конструкторе и переиспользуются;
- внутри агента: проверка запроса, формирование JSON с полным контекстом
  (`system` → предыдущие пары → новый `user`, каждое сообщение — отдельный объект
  массива `messages`), заголовки (`Content-Type`, `Authorization: Bearer`,
  `x-opencode-session`), отправка, обработка HTTP-ошибок/таймаутов/сети
  и извлечение `choices[0].message.content`;
- обновление истории атомарно: новая пара user/assistant сохраняется **только
  после** успешного ответа, поэтому таймаут, HTTP-ошибка, некорректный JSON,
  пустой ответ или прерывание не повреждают историю и не создают дубликатов
  при повторном вводе.

`Main` не знает ни про HTTP, ни про JSON: он только читает консоль, выполняет
локальные команды и печатает `Агент: <ответ>`. Конфигурация передаётся агенту
через `Config` — глобального состояния нет. Так агент можно переиспользовать
в любом другом интерфейсе (например, в GUI или тестах) без изменений.

## Как работает память диалога

- Первым сообщением каждого запроса отправляется постоянная системная
  инструкция (роль `system`), затем — завершённые пары user/assistant,
  затем — новый запрос пользователя. Пример последовательности ролей
  во втором запросе: `system → user → assistant → user`.
- История не склеивается в одну строку — каждое сообщение передаётся
  отдельным объектом массива `messages`. **Контекст обеспечивает именно
  массив `messages`, а не идентификатор сессии**: заголовок
  `x-opencode-session` требуется шлюзом OpenCode Go для маршрутизации,
  сам по себе он память не обеспечивает.
- История хранится только в памяти процесса и исчезает после завершения
  работы (в том числе после `exit`/`quit`/`/exit`/Ctrl+D). На диск ничего
  не записывается.

### Ограничение роста контекста

`LlmAgent.MAX_HISTORY_TURNS = 20` — максимум завершённых пар user/assistant,
передаваемых в одном запросе (и хранимых в памяти). Важно понимать:

- это ограничение **числа реплик**, а не точный подсчёт токенов;
- длинные сообщения даже в пределах 20 пар могут превысить контекстное окно
  модели — размер окна намеренно не зашит в код;
- удалённые самые старые пары больше **не отправляются** в API;
- повторная передача истории в каждом запросе увеличивает расход входных
  токенов — чем длиннее беседа, тем дороже каждый запрос;
- при удалении старых сообщений соблюдаются целые пары: assistant никогда
  не остаётся без предшествующего user;
- если API откажет из-за размера контекста, агент покажет понятную ошибку
  с HTTP-статусом и **не будет** очищать историю автоматически — сократить
  беседу можно вручную командой `/reset`.

## Настройка окружения

Агент читает три переменные окружения (значение по умолчанию у модели отсутствует):

```bash
export LLM_API_KEY="YOUR_API_KEY"   # ключ API (никому не показывать, не коммитить)
export LLM_API_URL="https://opencode.ai/zen/go/v1/chat/completions"
export LLM_MODEL="glm-5.3-flash"
```

Ключ лежит в локальном файле `.env` в корне проекта (shell-строки `export ...`).
`.env` добавлен в `.gitignore` и не попадает в репозиторий.

> `System.getenv` не загружает файлы `.env` автоматически — их нужно загрузить
> командой `source` перед запуском.

### Запуск из терминала

```bash
cd ai-advent-agent
mvn clean package          # сборка
source .env                # загрузить переменные в текущую сессию терминала
mvn compile exec:java      # запустить агент
```

Локальный самотест без платных запросов:

```bash
mvn test-compile exec:java@self-test
```

### Запуск одной командой на macOS

Требования: JDK 21+, Maven (или Maven Wrapper `./mvnw` в проекте) и локальный
`.env` в корне с тремя переменными (см. «Настройка окружения»).

Основной способ — одна команда из корня проекта:

```bash
./start-agent.sh
```

Что происходит: скрипт определяет директорию проекта по своему расположению,
открывает **отдельное окно Terminal.app** и запускает в нём внутренний скрипт
`run-agent.command`, который загружает `.env`, проверяет JDK 21+ и Maven
(использует `./mvnw`, если он есть, иначе системный `mvn`), собирает проект
и запускает интерактивный чат. Исходное окно терминала чатом не становится
и завершения диалога не ждёт. IntelliJ IDEA для работы не нужна.

Альтернатива — двойной щелчок по файлу `run-agent.command` в Finder: он делает
то же самое в новом окне Terminal. Если права ещё не выданы, выполните один раз:

```bash
chmod +x start-agent.sh run-agent.command
```

Диагностика (выводится в новом окне, запуск завершается с ненулевым кодом):

- нет JDK 21+ — сообщение с подсказкой установить JDK; скрипт также ищет
  подходящую JDK стандартным инструментом macOS (`/usr/libexec/java_home`);
  JDK, выбранная только в IDEA, оболочке недоступна — нужен установленный
  в системе JDK;
- нет Maven и `./mvnw` — подсказка установить Maven (например,
  `brew install maven`) или добавить Maven Wrapper;
- нет `.env` или пустая обязательная переменная — сообщение с именем файла
  и переменной (значения не печатаются);
- ошибка сборки — полная диагностика Maven, запуск агента не выполняется.

Примечания:

- первая сборка может требовать интернет для загрузки Maven-зависимостей;
- macOS может запросить разрешение на управление Terminal («…хочет
  управлять Terminal») — это штатный механизм безопасности для AppleScript;
  разрешите доступ один раз, системные механизмы безопасности не отключаются;
- скрипты не закрывают и не изменяют другие окна Terminal; окно с агентом
  после завершения остаётся открытым — закройте его вручную (автозакрытие
  зависит от настроек Terminal);
- `.env` загружается через `source`, то есть выполняется как shell-код:
  держите в нём только собственные настройки и не берите такой файл
  из недоверенных источников; `.env` остаётся в `.gitignore`.

### Запуск кнопкой Run в IntelliJ IDEA

1. Откройте `Main`, вызовите Run → Edit Configurations… → найдите конфигурацию
   приложения `Main` (или создайте: `+` → Application).
2. В поле **Environment variables** добавьте три переменные (кнопка иконки списка
   позволяет ввести их построчно):

   ```
   LLM_API_KEY=YOUR_API_KEY;LLM_API_URL=https://opencode.ai/zen/go/v1/chat/completions;LLM_MODEL=glm-5.3-flash
   ```

3. Сохраните и запускайте конфигурацию кнопкой Run.

Важно: `source .env` в терминале меняет окружение только этой сессии терминала.
Окружение **уже запущенной** IDEA от этого не меняется — для запуска кнопкой
переменные нужно указать в Run Configuration (см. выше), либо перезапустить IDEA
из терминала, где выполнен `source .env`.

## Установка командой ai-agent (текущий терминал)

Однократная установка из корня проекта:

```bash
./install-cli.sh
```

Установщик без sudo: собирает исполняемый JAR со всеми зависимостями
(Maven Shade) и устанавливает команду `ai-agent` в `~/.local/bin`.
Ключ никуда не записывается: launcher при каждом запуске читает локальный
`.env` проекта и передаёт переменные процессу Java через окружение.

Если `~/.local/bin` отсутствует в PATH, установщик выведет инструкцию
(дочерний процесс не может изменить PATH родительского терминала):

```bash
export PATH="$HOME/.local/bin:$PATH"   # текущая сессия
# постоянно (zsh): добавить ту же строку в ~/.zshrc и выполнить: source ~/.zshrc
```

После настройки PATH команда доступна из любого каталога:

```bash
ai-agent          # интерактивный чат в текущем терминале
ai-agent --plain  # без цветов, спиннера и сложного редактирования
ai-agent --help   # справка по запуску, не требует API-ключа
```

Приложение запускается в текущем терминале, без новых окон; IDEA не нужна.
После выхода вы возвращаетесь в исходный shell с прежним каталогом.
Автоматический упрощённый режим включается при перенаправленном вводе/выводе
и при `TERM=dumb`; переменная `NO_COLOR` отключает цвета.

Важно: установленная команда привязана к директории проекта на момент
установки. Повторный `./install-cli.sh` пересобирает приложение и обновляет
команду; после перемещения проекта нужна повторная установка. Если JAR в
`target/` удалён (например, после `mvn clean`), launcher предложит запустить
установщик заново. Старые скрипты `start-agent.sh` / `run-agent.command`
(отдельное окно Terminal.app) продолжают работать.

При запуске через launcher значения из `.env` имеют приоритет над одноимёнными
переменными текущего shell. `.env` загружается средствами shell (без `eval`)
и исполняет свои строки как shell-код: доверяйте только собственному файлу.

### Интерфейс чата

- При старте — компактный блок: имя, модель, «Контекст текущей беседы
  включён», подсказка команд; экран автоматически не очищается,
  alternate screen не включается — прокрутка средствами терминала работает.
- Приглашение «Вы ›», ответы с заголовком «Агент», пустая строка между
  репликами; ответы печатаются в исходном виде (переносы, отступы,
  Markdown-разметка); управляющие последовательности из текста модели
  обезвреживаются.
- Во время запроса — «Ожидаем ответ…» с реально прошедшим временем и
  спиннером (после ответа или ошибки строка стирается, курсор восстанавливается).
  Токены, стоимость и проценты не имитируются; потоковой генерации нет —
  ответ показывается целиком.

Команды (не вызывают API):

| Команда | Действие |
|---|---|
| `/help` | справка по командам |
| `/history` | история текущего диалога с ролями |
| `/reset` | очистить контекст и начать новую беседу (с подтверждением, если история непуста) |
| `/clear` | очистить экран, **не** удаляя историю (отличие от `/reset`) |
| `/multiline` | многострочный ввод |
| `/exit` | выход (также `exit`, `quit`) |

Многострочный режим: после `/multiline` все строки считаются содержимым
сообщения; отдельная строка `/send` отправляет накопленный текст одним
сообщением (до этого API не вызывается), `/cancel` отменяет набор,
пустой текст не отправляется. Универсальный Shift+Enter не обещается —
поведение зависит от терминала.

Ввод: редактирование строки, стрелки вверх/вниз — предыдущие введённые
сообщения (история ввода только в памяти), Tab — автодополнение команд.
Ctrl+C на строке ввода отменяет текущий ввод и возвращает новое приглашение;
Ctrl+C во время запроса завершает приложение, возвращая терминал
в исходное состояние (прерывание не отменяет обработку или оплату уже отправленного
запроса у провайдера). Ctrl+D на пустом вводе завершает приложение.
После обычной сетевой ошибки чат можно продолжить.

## Работа с агентом


- Введите запрос и нажмите Enter — агент выведет `Агент: <ответ>` с учётом
  истории текущей беседы.
- Локальные команды (без вызова API):
  - `/help` — справка по командам;
  - `/history` — показать сохранённые сообщения с ролями (user/assistant);
    если история пуста, выводится «История диалога пуста.»;
  - `/reset` — начать новую беседу: очищает историю и меняет session ID;
    выводит «Начата новая беседа. История очищена.»;
  - `/exit` — завершить приложение.
- Пустая строка пропускается (запрос к API не отправляется).
- `exit` или `quit` — выход без запроса к API. Ctrl+D (EOF) и Ctrl+C также
  завершают приложение. После выхода история диалога теряется.
- После сетевой ошибки можно ввести следующий запрос; неудавшийся запрос
  в историю не попадает. Автоматических повторов нет — чтобы не создавать
  платные запросы.

## Особенность эндпоинта OpenCode Go

Эндпоинт `/zen/go/v1/chat/completions` (подписка OpenCode Go) требует заголовок
`x-opencode-session` со стабильным идентификатором беседы — без него сервер
возвращает HTTP 400 `MissingSessionID` (см. документацию провайдера
`opencode.ai/docs/go`). `LlmAgent` генерирует UUID при создании агента
и отправляет его в каждом запросе одной беседы; после `/reset` создаётся
новый идентификатор. Для обычного эндпоинта `/zen/v1/chat/completions`
этот заголовок не требуется.

Ещё раз: session ID нужен шлюзу для маршрутизации и кэширования, **память
диалога он не обеспечивает** — контекст всегда передаётся явно через массив
`messages` (см. раздел «Как работает память диалога»).
